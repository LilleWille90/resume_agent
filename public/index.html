SongAtlas

A different way into the world’s music.

What are people listening to around the world? SongAtlas turns that question into a country-by-country music discovery experience, with weekly charts from more than 100 countries, genres, short previews and a collection of tracks to take with you.

Live web project · free and non-commercial

Open SongAtlas ↗

Behind the project

My contribution
I took the idea from a personal question to a published service, shaping the discovery experience and building it with AI-assisted development.
How AI fits
AI supported the implementation and iteration. The music experience itself uses chart data and catalog integrations; it is not an AI-generated ranking.
A product decision
Make the sources and limits visible. The service explains how charts are combined, distinguishes missing metadata from zero results, and handles different export paths for different music services.
What I’m learning
A playful starting point leads to real product questions: data freshness, matching recordings, API budgets and what to show when a source is unavailable.

Technical detail

A Cloudflare-hosted web app that rebuilds each country’s top 10 every week from licensed chart data, then matches every recording to Apple Music for artwork and previews.

  1. Fetch national charts via Soundcharts
  2. Join charts on recording IDs
  3. Score with equal weight
  4. Cache weekly in Cloudflare D1
  5. Match ISRC in Apple Music
  6. Preview, like and export
Front end
React and TypeScript on Vinext, a Vite-based implementation of the Next.js API. An orthographic D3 globe with a small WebGL renderer for the landscape view. Natural Earth relief textures are bundled (under 1 MB), so there are no map-vendor keys or per-view map calls.
Chart data
The Soundcharts API is the single ranking source: Spotify and Apple Music national daily charts, plus QQ Music (China), Melon (South Korea) and JioSaavn (India) where they lead the market. Charts are combined with equal weight through Soundcharts recording UUIDs; a country with only one chart is shown without aggregation.
Media matching
Apple Music catalogue lookup by exact ISRC in the right storefront, with no fuzzy title search. 30-second previews stream from Apple and no audio is stored. Without an exact match the track gets a placeholder rather than a guess.
Playlist export
Apple Music through MusicKit JS and a short-lived developer token signed on the server, so the private key never reaches the browser. Playlists are private, de-duplicated and only ever added to. Spotify and YouTube Music export use links resolved through Soundcharts and need no sign-in.
Storage and caching
Cloudflare D1 (SQLite) with Drizzle ORM. A shared weekly cache refreshes on the first visit after Friday 18:00 CET, saved chart snapshots drive “biggest climber”, and ISRC matches are cached for 30 days. Liked tracks stay in the browser (up to 100).
Privacy and cost control
No cookies or tracking; usage is counted as anonymous daily totals per country. Calls to the data provider run under a hard budget and metadata is fetched in small batches for visible tracks only. Retired sources (direct Apple charts, Deezer, Spotify scraping) are switched off at the API.

BikerBrain

Cycling data that has to earn your trust.

A connected cycling app exploring how GPS, sensors, weather and route signals can become useful ride insights, including estimated power and activity analysis.

Beta 1.2 for iPhone, in active development · walkthrough on request

Behind the project

My contribution
I lead the product concept and hands-on development, working through the cycling experience, sensor integration, diagnostics and validation with AI tools.
How AI fits
Coding agents support implementation, debugging, testing and documentation. Estimated cycling power is a model output that needs validation; using AI to build the app does not make its measurements accurate by default.
A product decision
Keep the measurement core understandable and testable. Compare ride recordings and sensor data, investigate discrepancies, and separate calculated signals from explanatory features.
What I’m learning
Getting a feature to run is only the beginning. Physical sensors, noisy data and real rides expose assumptions that a convincing prototype can hide.

Technical detail

A native, local-first iPhone app. Recording, sensor input, power estimation and post-ride analysis run on the device and keep working without a connection.

  1. GPS, barometer and BLE sensors
  2. Select speed, gradient and acceleration
  3. Physics-based power estimate
  4. Route and weather context
  5. Local history and analysis
  6. CSV and FIT export
Platform
Swift and SwiftUI with Combine, Swift Charts, MapKit and ActivityKit (Live Activity on the Lock Screen). Layered architecture: SwiftUI features → platform services → a pure, deterministic domain layer with no UI, Bluetooth or network dependencies.
Sensors
Core Bluetooth with standard BLE GATT profiles: Cycling Speed and Cadence (0x1816), Heart Rate (0x180D) and Device Information. A Cycling Power meter (0x1818) is read only as an independent reference and never feeds the estimate. Core Location for GPS and Core Motion for barometric altitude.
Power model
A deterministic physics model of gravity, rolling resistance, aerodynamic drag and acceleration, using rider and bike mass from a versioned bike profile. Heart rate never influences power. The model is under a “model freeze”: changes need evidence from replayed real rides and regression tests.
Weather and routes
Apple WeatherKit, with MET Norway’s Locationforecast API as an alternative provider, supplies temperature and pressure for air density; wind is evaluated separately. GPX import, on-device route recognition and learned segments, with optional elevation data from MapTiler.
Data and export
A versioned CSV contract with JSONL sidecars for diagnostics, plus a native FIT encoder. Ride data stays on the phone by default, protected by iOS Data Protection, with credentials in the Keychain. Prepared but not switched on: Strava upload through a server-side OAuth gateway, and a Supabase account layer with Sign in with Apple.
Quality
About 600 automated tests (Swift Testing and XCTest) and 48 architecture decision records. Estimates are compared with power-meter recordings through reproducible ride replays and agreement reports.

Wavemap

Music has a place. Explore it.

An interactive atlas connecting music, artists, places and eras. The project began as Hip-hop Atlas and explores how a map can invite discovery beyond a conventional list or search box. Today the Wavemap front page opens maps for hip hop, rock and electronic music.

Interactive web project · formerly Hip-hop Atlas

Open Wavemap ↗

Behind the project

My contribution
I shape the product concept and exploration experience, using AI-assisted development to build and iterate on the map, artist information and visual direction.
How AI fits
AI is part of the building and design workflow. The aim is an interactive music experience, with geography and context giving people another way to explore.
A product decision
Let location be part of the interface. Connecting artists to places and eras turns navigation into an act of discovery.
What I’m learning
A rich visual world needs clear interactions. The challenge is balancing atmosphere, readable information and navigation that makes sense.

Technical detail

A browser-based 3D atlas: a MapLibre map with three.js scenes drawn as custom layers. Every city, artist, place and era is typed data rather than map code.

  1. Typed content with sources
  2. Self-built relief and terrain
  3. MapLibre map with three.js layers
  4. Generated 3D models and sound
  5. Previews looked up at runtime
Stack
TanStack Start (React, server rendering, file-based routes) in TypeScript, MapLibre GL, three.js and React Three Fiber, Tailwind and Radix UI. Built with Lovable and synced from GitHub; tests run on Bun.
Map and world
Natural Earth shaded relief and NOAA ETOPO elevation, processed by a Python build script into bundled terrain, borders and labels, with no third-party map tiles. Cities are 3D dioramas generated from skyline data.
Content model
Typed data for scenes, about 150 artist cards, places, eras and sounds. Every claim carries its sources and contested claims are labelled. Genre packs for hip hop, rock and electronic music sit behind the Wavemap front page.
Generated assets
Landmarks, props and figures from Meshy’s text-to-3D API, optimised with glTF-Transform (Meshopt compression, WebP textures). Sound effects from the ElevenLabs API, loudness-normalised with ffmpeg; anything missing falls back to synthesised Web Audio.
Music and content rules
30-second previews are looked up at runtime through Apple’s public iTunes Search API, and nothing is stored. Only original generated or synthesised sounds are used, never samples, and real tragedies are shown through their aftermath only. All motion respects reduced-motion settings.

Storytailor

From a spoken story to a book to keep.

A recorded family story becomes a personal, illustrated and printable children’s book. The project brings transcription, story structure, illustration and print production into one guided journey.

Independent service project · walkthrough on request

Behind the project

My contribution
I defined the customer journey and built the service across UX, engineering, model integrations, payments and print fulfilment.
How AI fits
Different models handle transcription, structured story work and illustration. The workflow combines OpenAI, Claude and image generation through Replicate, followed by layout and print preparation.
A product decision
Design the whole journey, including recovery. Character consistency, malformed structured output and print-layout constraints need attention between model calls.
What I’m learning
The value lies in orchestration: a sequence of powerful models only becomes a useful service when quality checks and recovery paths hold the experience together.

Technical detail

A React app with a Supabase backend, where Netlify Functions orchestrate a chain of models from a voice recording to a printed and shipped book.

  1. Record in English or Swedish
  2. Transcribe
  3. Extract characters and world
  4. Split into pages
  5. Illustrate consistently
  6. Lay out a print PDF
  7. Pay, print and ship
Stack
React 19 and Vite; Supabase for Auth, Postgres with row-level security, and Storage for audio, images and PDFs; Netlify Functions, including a background function; @react-pdf/renderer for print-ready PDFs; Capacitor for an iOS build.
Language models
OpenAI Whisper transcribes Swedish and English. Claude Haiku 4.5 handles the fast structured steps: character extraction, style guides and visual prompts. Claude Sonnet 4.6 splits stories into pages, suggests illustrations and analyses uploaded style reference images.
Images and audio
Black Forest Labs FLUX 1.1 Pro on Replicate creates character reference images; FLUX Kontext Pro uses them to keep characters consistent from page to page. OpenAI text-to-speech reads stories aloud.
Payments and print
Stripe Checkout with a verified webhook, followed by the Lulu Print API (OAuth client credentials) for print-on-demand production and shipping.
Engineering
All API keys stay server-side in functions; the browser holds only Supabase’s public key. Image calls back off and retry when rate-limited, and the PDF layout includes bleed for Lulu’s print specification.
